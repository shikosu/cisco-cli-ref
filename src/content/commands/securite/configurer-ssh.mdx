## En bref

**SSH** (Secure Shell) chiffre les sessions d'administration distante. C'est le successeur de Telnet,
qui transmettait les mots de passe en clair. SSH est **obligatoire** en environnement pro.

Pour activer SSH, il faut **4 conditions** :

1. Un **hostname** (autre que `Switch`/`Router` par défaut)
2. Un **domain-name** (n'importe lequel)
3. Une **paire de clés RSA** ≥ 1024 bits
4. Un **utilisateur local** + autorisation SSH sur les lignes VTY

## Syntaxe

<CodeBlock lang="cisco">
hostname &lt;nom&gt;
ip domain-name &lt;domaine&gt;
crypto key generate rsa
username &lt;user&gt; privilege 15 secret &lt;mdp&gt;
line vty 0 4
 login local
 transport input ssh
</CodeBlock>

## Exemple minimal

<CodeBlock lang="cisco" title="Configuration SSH complète" showLineNumbers={true} highlight={[3, 7, 8, 12]}>
SW-Lattes-01> enable
SW-Lattes-01# configure terminal
SW-Lattes-01(config)# ip domain-name lycee-champollion.fr
SW-Lattes-01(config)# crypto key generate rsa
The name for the keys will be: SW-Lattes-01.lycee-champollion.fr
How many bits in the modulus: 2048
SW-Lattes-01(config)# username admin privilege 15 secret M0nMdP!
SW-Lattes-01(config)# line vty 0 4
SW-Lattes-01(config-line)# login local
SW-Lattes-01(config-line)# transport input ssh
SW-Lattes-01(config-line)# end
SW-Lattes-01# write memory
</CodeBlock>

## Étapes détaillées

**1. Vérifier que le hostname n'est pas par défaut**

Depuis <CliPrompt mode="privileged" />, tape `show running-config | include hostname`.
Si tu vois `hostname Switch`, [change-le d'abord](/commands/bases/configurer-hostname).

**2. Définir un domain-name**

<CodeBlock lang="cisco">
Switch(config)# ip domain-name lycee-champollion.fr
</CodeBlock>

Ce domaine n'a pas besoin d'exister — il sert juste à nommer les clés RSA.

**3. Générer la paire de clés RSA**

<CodeBlock lang="cisco">
Switch(config)# crypto key generate rsa
How many bits in the modulus: 2048
</CodeBlock>

<Callout type="tip" title="Taille du modulus">
  **Minimum 1024**, recommandé **2048**. Plus c'est grand, plus c'est sécurisé,
  mais plus la génération est lente. 2048 est le bon compromis pour les TP.
</Callout>

**4. Créer un utilisateur local**

<CodeBlock lang="cisco">
Switch(config)# username admin privilege 15 secret M0nMdP!
</CodeBlock>

`privilege 15` = niveau max (équivalent enable). `secret` = stockage chiffré (vs `password` en clair).

**5. Configurer les lignes VTY**

<CodeBlock lang="cisco">
Switch(config)# line vty 0 4
Switch(config-line)# login local
Switch(config-line)# transport input ssh
</CodeBlock>

- `login local` → utilise la base locale (pas un mot de passe partagé)
- `transport input ssh` → **n'autorise que SSH** (refuse Telnet)

## Vérification

Depuis ton poste admin :

<CodeBlock lang="bash">
ssh admin@192.168.1.1
</CodeBlock>

Ou côté équipement :

<CodeBlock lang="cisco" title="Vérifier SSH">
SW-Lattes-01# show ip ssh
SSH Enabled - version 2.0
Authentication timeout: 120 secs; Authentication retries: 3
</CodeBlock>

## Pièges fréquents

<Callout type="danger" title="Ne mets jamais transport input telnet">
  Telnet transmet les mots de passe en **clair sur le réseau**. C'est une faute en évaluation.
  Toujours `transport input ssh`.
</Callout>

<Callout type="warning" title="Hostname par défaut = erreur">
  Si tu lances `crypto key generate rsa` sur un équipement nommé `Switch` ou `Router`,
  l'IOS refuse. **Changer le hostname est un prérequis.**
</Callout>

<Callout type="tip" title="Forcer SSH v2 uniquement">
  SSH v1 a des vulnérabilités connues. Force la v2 avec `ip ssh version 2`.
</Callout>

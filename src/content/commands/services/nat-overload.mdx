## En bref

Le NAT Overload (ou PAT — Port Address Translation) permet à **tous les hôtes d'un réseau privé** de partager **une seule adresse IP publique** pour accéder à Internet. Le routeur distingue les sessions grâce aux numéros de port source. C'est la configuration standard dans les box/routeurs domestiques et d'entreprise.

## Topologie de référence

<Topology>
[PC1 192.168.1.10]──┐
[PC2 192.168.1.11]──┤──[Gi0/0]──[R1 NAT]──[Gi0/1]──Internet
[PC3 192.168.1.12]──┘    inside            outside
                         priv              203.0.113.1 (IP publique)

PC1 → Internet : 192.168.1.10:12345 → 203.0.113.1:12345
PC2 → Internet : 192.168.1.11:54321 → 203.0.113.1:54321
Le routeur mémorise la correspondance port ↔ hôte privé.
</Topology>

## Configuration étape par étape

**1. Créer une ACL standard définissant les hôtes à NATer**

<CliPrompt mode="config" />

<CodeBlock lang="cisco">
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
</CodeBlock>

**2. Marquer l'interface interne (LAN)**

<CliPrompt mode="config-if" />

<CodeBlock lang="cisco">
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# ip nat inside
Router(config-if)# no shutdown
Router(config-if)# exit
</CodeBlock>

**3. Marquer l'interface externe (WAN / Internet)**

<CodeBlock lang="cisco">
Router(config)# interface GigabitEthernet0/1
Router(config-if)# ip address 203.0.113.1 255.255.255.252
Router(config-if)# ip nat outside
Router(config-if)# no shutdown
Router(config-if)# exit
</CodeBlock>

**4. Configurer le NAT Overload**

<CliPrompt mode="config" />

<CodeBlock lang="cisco" title="NAT Overload — ACL 1, interface WAN">
Router(config)# ip nat inside source list 1 interface GigabitEthernet0/1 overload
</CodeBlock>

Le mot-clé `overload` active le PAT (plusieurs hôtes → une seule IP publique).

**5. Configurer la route par défaut vers Internet**

<CodeBlock lang="cisco">
Router(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.2
</CodeBlock>

<CodeBlock lang="cisco">

</CodeBlock>

Utile pendant le débogage pour forcer de nouvelles entrées.

## Pièges fréquents

<Callout type="danger" title="ip nat inside et ip nat outside sont obligatoires sur CHAQUE interface">
  Sans `ip nat inside` sur l'interface LAN et `ip nat outside` sur l'interface WAN, le NAT ne fonctionne pas du tout. C'est l'erreur la plus fréquente en TP.
</Callout>

<Callout type="warning" title="L'ACL doit correspondre exactement aux adresses du LAN">
  Si l'ACL est trop restrictive (ex: `permit host 192.168.1.10` alors que tu as aussi 192.168.1.11), les hôtes non inclus dans l'ACL ne seront pas translatés et n'auront pas accès à Internet.
</Callout>

<Callout type="tip" title="Tester avec ping depuis un PC vers 8.8.8.8">
  Pour vérifier que le NAT fonctionne, ping depuis un PC du LAN vers une IP publique (ex: `8.8.8.8`). Si le ping passe, regarde `show ip nat translations` pour confirmer la traduction.
</Callout>
